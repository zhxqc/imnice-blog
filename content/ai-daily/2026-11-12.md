## 模型 / 产品

### 1. Google 发布 Gemini Decisions API 与 Gemini Decision 1
- **背景：** 智能体里大量分支其实是「是否 / 多选 / 打分」这类封闭问题，不必逐 token 生成长文本。OpenAI 等已有类似决策接口；Google 这次把多模态（含音视频和 PDF）一次性评估做成专用 endpoint。
- **发生了什么：** 官方博客 JSON-LD 的 `datePublished` 为 **2026-11-11T18:00:00+00:00**（北京时间 **11 月 12 日 02:00**）。新接口由 **Gemini Decision 1** 驱动，经 Gemini API（示例为 `v1beta` 的 `client.decisions.create`）在 Google AI Studio 提供。一次前向传播可对同一输入（文本、图像、音频、视频、PDF，最多 **256K tokens**）评估最多 **1,000** 道彼此独立的题：`noul`（是否）、`choice`（2–255 选项）、`score`（从 0 起的有序量表），每项带 0–1 置信度。延迟：端到端 **150–250 ms**，模型计算中位 **50–100 ms**（文中写该中位数字适用于最多 16K tokens、1 到 100 题几乎持平）。定价：**$0.10 / 1M input tokens**，**output 计费为 $0**；共享 input 按请求只计一次。厂商称在其共享基准上较 Gemini 3.5 Flash-Lite + Interactions API「nearly 5x cheaper」，并称 Notebook、Stitch、Labs、Search 等内部已在用。生态方面提到 OpenRouter、LangChain、Vercel 等接入；Google Cloud 上的 Gemini 支持「即将到来」。
- **为什么重要：** 把「分类器 / 路由 / 策略检查」从通用生成模型里拆出来，可能显著压低 Agent 内循环的成本和延迟；基准领先与「5 倍更便宜」仍是**官方测试**，完整对外榜单未在该页给出。
- **开放方式 / 规模 / 上下文 / 许可证：** AI Studio 可领 API key；无开源权重（官方未披露）；Cloud 支持未上线。
- **来源：** [Gemini Decisions API 官方博客](https://blog.google/innovation-and-ai/technology/developers-tools/gemini-decisions-api/)

### 2. Runway 以 Apache 2.0 开放 Praxis-1 权重与代码
- **背景：** Praxis-1 是 Runway 在 9 月介绍的「世界-动作模型」：同时预测未来视频和机器人动作。此前主要给 Noble Machines、Standard Bots、Ultra 等合作伙伴在自有硬件上跑；本期新事实是对所有人开放权重。
- **发生了什么：** 官方新闻页 `datePublished` 为 **2026-11-11T15:00:00.000Z**（北京时间 **23:00**）。模型为 **27B** 参数 MoE 扩散 Transformer。权重与推理/微调代码（含全量微调与 LoRA）以 **Apache 2.0** 发布，可商用；渠道包括 GitHub（[runwayml/praxis-1-oss](https://github.com/runwayml/praxis-1-oss)）、Hugging Face（LeRobot 原生支持）、vLLM-Omni，以及 Reactor 托管推理。硬件声明覆盖 H100、B200、RTX 5090、RTX PRO 6000 和 Jetson Thor。厂商称在 NVIDIA **RoboLab-120**（截至 2026 年 11 月、1,200 局）成功率 **46.2%**，对照 FLUX 3 Action 42.9%、Cosmos3 Nano 36.8%、π0.5 28.0%；在未见过训练数据的 Google RT-1 上微调后，SimplerEnv 成功率 **80.0%**（原 RT-1 策略 52.4%）。这些均为**厂商披露**。
- **为什么重要：** 把视频预训练直接接到可商用的开源机器人策略，降低「自有硬件上微调世界模型」的门槛；榜单数字仍需对照独立评测。
- **开放方式 / 规模 / 上下文 / 许可证：** Apache 2.0；HF 上有 `praxis-1-base` / `praxis-1-droid` / `praxis-1-yam` 及 NVFP4 变体。
- **来源：** [Runway 新闻稿](https://runway.com/news/company-news/praxis-1-is-now-available) · [Hugging Face 合集](https://huggingface.co/collections/runwayml/praxis-1) · [GitHub](https://github.com/runwayml/praxis-1-oss)

## 论文

窗口对应 arXiv **周三 2026-11-11** 新清单（北京时间今日 09:00 公布；去重后新稿 523 篇）。精选如下；实验数字均为**论文自行报告**。昨日周二清单中的 Homeopathic Learning、CyberBinGym 等今日无新版本，不重复。另补一条 11 月 11 日 Anthropic 博客（对应论文已于 9 月 30 日提交）。

### 1. ExpertCrowd-SWE：用专家出题衡量陌生代码库上的编码智能体（首次提交，周三清单）
- **核心贡献：** Toptal ExpertCrowd 提出 100 道由在职工件师撰写的多文件任务，覆盖 87 个开源项目、11 种语言，针对「大型、陌生仓库」中的自主编码智能体。评分带部分分和 must-pass 门槛，而不是只看公开测试是否通过。
- **与已有方法的区别：** 作者认为 SWE-bench 谱系的修复讨论与测试往往已经公开、可能进入预训练；本题由熟悉该库的专家出题，并按当前前沿模型的难度筛选。评测暴露各厂商原生工具接口，而不是统一 bash。
- **关键实验：** 7 个模型各 5 次、共 3,495 次计分。宏平均任务分（95% CI）：**Claude Opus 5.5 67.3±4.7**，**GPT-6 Astra 63.7±5.5**（二者无统计显著差距），随后是 Claude Fable 5.1 **46.5±3.7**、Gemini 3.8 Flash **40.0±4.3**，以及 Qwen 3.8 Max、DeepSeek V4.1 Flash、Grok 4.6（约 32–33 分）。没有一道题被所有模型完全做对。
- **代码/数据：** 部分开放——发布 24 题，76 题留作防污染 hold-out。[HF 数据集](https://huggingface.co/datasets/ExpertCrowd/ec-swe) 抓取时可访问；排行榜页本次 403，不宣称当时可打开。
- **链接：** [arXiv:2611.13246](https://arxiv.org/abs/2611.13246)

### 2. 企业 SOP 上的 Agent 架构：成本与成功率权衡（首次提交，周三清单）
- **核心贡献：** Amazon / 华盛顿大学在模型、任务与工具固定时，比较单智能体、技能增强、中心化多智能体与分诊 swarm 等八个实验臂，覆盖 13 条企业风格 SOP。
- **与已有方法的区别：** 把「智能体架构」从模型和工具里单独拆出来做受控对比，并引入技能定义质量量表。
- **关键实验：** 总体上看，各架构在合计成功率上难以统计区分，但不同 SOP 的成功率从不到 10% 到接近 100%。协同臂的 token 消耗为单智能体的 **1.4–4.7×**、延迟 **2.6–5.8×**。高质量技能把成功率从 67.4% 提到 **73.1%**，劣化技能降到 59.8%；重新设计的多智能体臂是唯一显著超过基线的（**75.6% vs 67.4%**）。论文概括：单智能体常常是成本上的默认选择，实现质量往往比「要不要上多智能体」更重要。
- **代码/数据：** 未披露。
- **链接：** [arXiv:2611.12953](https://arxiv.org/abs/2611.12953)

### 3. Veritas：为 Agent 任务自动生成校验器（首次提交，周三清单）
- **核心贡献：** 字节跳动 / 伊利诺伊大学芝加哥分校 / 纽约大学提出自动生成 verifier 的 harness，用来给 Agent 轨迹打「是否真正完成任务」的分。
- **关键实验：** 固定 GLM-5.2 时，Veritas 的 Cohen’s κ* 在四个以执行为准的基准上优于 7 种普通 harness，例如 τ²-bench **0.787**（次高 Claude Code 0.726）、SWE-bench Verified **0.720**。
- **代码/数据：** 未披露。
- **链接：** [arXiv:2611.13336](https://arxiv.org/abs/2611.13336)

### 4. 编码 harness 的组合式安全（首次提交，周三清单）
- **核心贡献：** 讨论编码智能体运行时的攻击面，主张用分层、可组合的防护（而非只靠 LLM 法官）挡住 Living-off-the-Land 类滥用。
- **关键实验：** 252 个测试夹具。论文称本地 LLM 法官（qwen3:4b）会拒绝 **98.3%** 的良性工作（142.3 ms），而 Ring 0 在 **12.7 µs** 内达到 ABR=1.000、FPR=0.000（均为作者报告）。
- **代码/数据：** 未披露。
- **链接：** [arXiv:2611.13960](https://arxiv.org/abs/2611.13960)

### 5. TopicScope：在 prefill 上训练、在 decode 时做主题监视（首次提交，周三清单）
- **核心贡献：** 用稀疏自编码器（SAE，把隐状态压成少量可解释特征的小模型）做主题监视：在预填充阶段训练，部署到逐 token 生成。
- **关键实验：** Gemma-3 1B 上，无监督 summation 用 1,500 个特征即达到 macro-F1 **94.3–96.2**。代码开放。
- **代码/数据：** [Mercity-AI/SAE-Guardrails](https://github.com/Mercity-AI/SAE-Guardrails)（抓取时 HTTP 200）。
- **链接：** [arXiv:2611.12935](https://arxiv.org/abs/2611.12935)

### 6. Anthropic：「Worse Together」与 MAMUBench（补录）
- **核心贡献：** Anthropic Fellows 在四类「多用户共享资源、每人各有一个代理」的模拟环境里发现：每人各派一个代理的团队，群体结果都差于**一个代理服务所有人**。三个环境以 MIT 许可放在 [MAMUBench](https://github.com/safety-research/MAMUBench)。官方博客标 **November 11, 2026**（无精确时刻）；对应论文 [2610.00583](https://arxiv.org/abs/2610.00583) 已于 **2026-09-30** 提交，代码最后推送在 10 月 9 日，故按博客/基准披露补录，不当成今日新投稿。
- **关键实验（博客）：** 对两个 Claude 模型，coordinator 平均领先 peer-to-peer 约 **10–45 个百分点**。共享 API 预算环境里，团队扩大时真正行动的代理比例下降（4→16 人，Sonnet 5 从 66% 降至 10%）。指定队长或「读完消息才能下单」等平台护栏，能在部分环境挽回失败。数字来自受控模拟，不是生产流量。
- **来源：** [Anthropic Alignment 博客](https://alignment.anthropic.com/2026/worse-together/) · [arXiv:2610.00583](https://arxiv.org/abs/2610.00583) · [代码](https://github.com/safety-research/MAMUBench)
