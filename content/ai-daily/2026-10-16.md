## 模型 / 产品

### 1. Meta · Muse Spark Open（开源权重）
- **背景：** 闭源前沿模型把编码/Agent 能力推高后，美国阵营缺少可本地/自托管的对等开源权重；Meta 用 Muse 系列填这个空位。
- **发生了什么：** 2026-10-15 发布 Muse Spark Open：原生多模态（文本/图像/视频/音频输入 → 文本输出），**816B** 总参数、约 **42B** 激活、**1M** token 上下文；面向长程任务、复杂软件工程与多步推理。权重在 Hugging Face 等渠道提供 BF16（约 1.65 TB）与 NVFP4（约 537 GB）；托管推理含 Modal、OpenRouter、Together、Fireworks、Groq 等。宣称可在两台 Apple M5 Ultra Mac Studio + MLX 上本地跑通。另做了面向开源部署的额外安全后训练。
- **为什么重要：** 把「可自托管的前沿 Agent/编码模型」规格钉在 816B MoE + 1M 上下文；企业可评估本地/专有云部署，而不只依赖闭源 API。
- **开放方式 / 规模 / 许可证：** 开源权重 + 多云/API；规模见上；**Muse Model License**（含有限商业条款）。参数细节以模型卡为准。
- **来源：** [Meta Research](https://research.meta.ai/blog/muse-spark-open) · [HF 集合](https://huggingface.co/collections/meta-models/muse-spark-open) · [AIHOT](https://aihot.news/items/s80tw5g2v22j1se4bmqejyaq4)

### 2. Anthropic · Claude Code Review 正式可用（Team / Enterprise）
- **背景：** 编码 Agent 提高写码速度后，PR 审阅成为瓶颈；产品此前处于研究预览。
- **发生了什么：** 2026-10-15 宣布 Code Review 结束预览，面向 Claude Team 与 Enterprise。管理员启用、装 GitHub App 并选仓后，新 PR 自动审阅。相对预览：多数审阅约 **3×** 更快（约 20 分钟 → 6–10 分钟，厂商披露）；可按仓设 Quick / Standard / Deep。合格 Enterprise 组织可申领至少 **$10,000** Code Review 积分（至 2027-01-15，条款适用）。
- **为什么重要：** 把「自动审 PR」从实验功能推进到可采购的组织默认能力，直接对标编程 Agent 工作流的审阅层。
- **来源：** [Claude Blog](https://claude.com/blog/code-review-is-now-generally-available) · [AIHOT](https://aihot.news/items/wmxwoemumqiq2yfrjngl3a5rc)

### 3. Anthropic · Claude Opus 5.5 fast mode 结束研究预览
- **背景：** 同一模型权重下用更快推理配置换吞吐，是 Agent/IDE 场景的常见采购诉求。
- **发生了什么：** Opus 5.5（`claude-opus-5-5`）的 fast mode 不再需要 beta header / 等待名单；请求设 `speed: "fast"`。官方称输出 token/秒最高约 **2.5×**；定价 **$8 / $40 per MTok**（输入/输出）；已上 Claude API，并登陆 Microsoft Foundry（Azure 托管）。能力与标准模式相同，换的是推理配置而非新权重。
- **为什么重要：** 让「贵模型 × 长输出 Agent」在时延敏感路径上可算账；需注意 fast/standard 不共享 prompt cache。
- **来源：** [Fast mode 文档](https://platform.claude.com/docs/en/build-with-claude/fast-mode) · [AIHOT](https://aihot.news/items/e2ssy0a7scpnel6ppyl3r9f2t)

### 4. NVIDIA · Nemotron 3.5 Super VL（及 Bolt 端侧线）
- **背景：** 企业要「可后训练、可本地/专有云部署」的多模态 Agent 基座，而不是只能调闭源 API。
- **发生了什么：** 2026-10-15 发布开源 **Nemotron 3.5 Super VL**：约 **120B** 总参 / **12B** 激活，支持文本/图像/视频，上下文最高约 **1M**；厂商称同级任务完成速度可达约 **5×**（Artificial Analysis 等榜单口径，需独立复核）。同步推出 Bolt 74B-A9B（24GB，现已可用）与 Bolt E4B（4GB，约 10-23 上线）。权重、数据集与训练配方开放；许可证见模型卡 **OpenMDW-1.1**。
- **为什么重要：** 把「多模态 Agent 基座 + 开放后训练材料」捆成一条可落地的 NVIDIA 栈叙事，覆盖数据中心到桌面。
- **来源：** [NVIDIA Blog](https://blogs.nvidia.com/blog/nemotron-3-5-super-vl/) · [开发者博文](https://developer.nvidia.com/blog/nvidia-nemotron-3-5-super-vl-powers-specialized-agents-with-multimodal-reasoning/) · [AIHOT](https://aihot.news/items/l9jgzg24ei3a7m8xu1xfhy9n7)

## 论文

> 下列为窗口内 arXiv 新出现的首次提交（published 时间多为 2026-10-14 UTC 晚间批次）；昨日已报的 2610.141xx / ClawLoop 等不重复。

1. **Co-Evolving Acting and Forecasting for Language Agents**（首次提交，[arXiv:2610.20597](https://arxiv.org/abs/2610.20597)）
   - **核心贡献：** 针对长程 Agent RL「只有终态标量奖励、中间步监督浪费」的问题，联合训练行动策略与可构造的预测/预报目标，减少对难构造 value/observation target 的依赖。
   - **为什么重要：** 直接打在「长程 rollout 贵、中间信号用不起来」的训练瓶颈上。
   - **代码/数据：** 以论文声明为准（摘要未承诺全面开源）。

2. **Latent Compaction with Test-Time Training**（首次提交，[arXiv:2610.20582](https://arxiv.org/abs/2610.20582)）
   - **核心贡献：** 用测试时训练学习文档专用的紧凑 KV cache（Latent Compaction），初始化结合重建重要性、教师注意力与 key 空间多样性。
   - **为什么重要：** 长上下文推理的内存/算力税是生产 Agent 的硬约束；测试时压缩是有别于静态量化的路径。
   - **代码/数据：** 以论文声明为准。

3. **One Task, Many Interfaces**（首次提交，[arXiv:2610.20576](https://arxiv.org/abs/2610.20576)）
   - **核心贡献：** 指出后训练会把 Agent 能力绑死在训练时接口上；提出跨接口一致性训练，提升对动作改名/记法扰动的鲁棒性。
   - **为什么重要：** 解释了「换一套工具 schema 就崩」的工程痛点，对 MCP/多平台 Agent 有直接启示。

4. **Beyond LLM Judge: Mechanical Verification for Agentic Autoformalization**（首次提交，[arXiv:2610.20573](https://arxiv.org/abs/2610.20573)）
   - **核心贡献：** 在 Lean 形式化验证中，把 LLM 语义审查与机械数值/空性检查结合，捕捉 LLM judge 漏掉的错误；并提出 Extract-Verify-Proof 管线。
   - **为什么重要：** 形式化/自动定理证明若仍只靠 LLM 互评，会系统性漏检。

5. **Scaling Discovery Requires Forgetting**（首次提交，[arXiv:2610.20563](https://arxiv.org/abs/2610.20563)）
   - **核心贡献：** 观察自动科研 Agent 在拉长迭代、并行或互通后都会因历史累积而平台期，论证「遗忘/重置历史」对继续发现新想法的必要性。
   - **为什么重要：** 对「堆更多 Agent 小时数」的粗暴扩展提出反例与机制解释。

6. **PrismaCoder**（首次提交，[arXiv:2610.20538](https://arxiv.org/abs/2610.20538)）
   - **核心贡献：** 面向多模态代码智能（图表/网页/动画等），用分解式 rubric 合成推动开源多模态代码模型能力。
   - **为什么重要：** 闭源模型已能从截图/描述生成交互产物；开源侧需要可复现的数据与评测构造法。
