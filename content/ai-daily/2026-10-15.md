## 模型 / 产品

### 1. xAI · Grok Voice 3.0
- **背景：** 语音 Agent 要从「能聊天」走到可计价的客服/设备排障工作流；Tesla / SpaceX / Starlink 已是内部重度用户场景。
- **发生了什么：** 2026-10-14 官方宣布 speech-to-speech 模型 Grok Voice 3.0。Artificial Analysis（2026-10-13）称 Speech-to-Speech Index **86.9**（高于 Grok Voice 2.0 的 81.3、GPT-Live-1 Astra Medium 的 83.2、Gemini 3.8 Live 的 82.6）；Full Duplex Bench **97%**；任务成功率 **94.8%**。Voice Agent API 定价 **$0.08/分钟**（与 2.0 相同）；`grok-voice-latest` 已自动切到 3.0。参数量、上下文窗口、权重与开源许可证均为**官方未披露**。
- **为什么重要：** 把「延迟 × 任务完成率 × 单价」捆成可采购的语音 Agent 规格；与 Cursor / Grok Bot 同属 SpaceXSI 分发叙事下的又一落地层。
- **注意：** 榜单为第三方评测 + 厂商引用；首音频时延等分项未必全面领先前代。
- **来源：** [xAI 公告](https://x.ai/news/grok-voice-3) · [AIHOT](https://aihot.news/items/qld0z3p2gztpolbmviizsm66u)

### 2. Google Research · Deep Review 公开发布
- **背景：** AI 加速写稿后，审阅成为瓶颈；Deep Review 前身 PAT 曾在顶会投稿前向作者提供可选反馈。
- **发生了什么：** 2026-10-14 公开发布。流水线：文档切分 → 按信息密度自适应算力 → 多专长 Agent 并行验证 → 全局综合与外部检索 grounding。试点覆盖 STOC 2026、ICML 2026、NeurIPS 2026、ICLR 2027 等超过 **16,000** 篇投稿；现支持 PDF/纯文本，每周两次免费额度，也可接 Gemini API。文档**不用于**训练 Google 模型。Antigravity 侧提供 Teamwork Deep Document Review Pattern（`/teamwork-preview`）。
- **为什么重要：** 「分段并行验证 + 全局复核」把审稿从一次摘要变成可追溯检查；对企业设计文档与合规材料同样适用。
- **开放方式 / 规模 / 许可证：** 门户 + API；底层模型规模**官方未披露**；非开源权重。
- **来源：** [Google Research](https://research.google/blog/analyzing-technical-documents-with-deep-review/) · [Deep Review 入口](https://research.google/deepreview/) · [AIHOT](https://aihot.news/items/enqtz3wtz6khvf0m44z5a5jaz)

### 3. OpenAI · 用 GPT-6 系列维护大型代码库（工程博文）
- **背景：** Agent 写代码加快后，死代码、陈旧实验与 flaky 测试的维护债同步膨胀。
- **发生了什么：** Core Experimentation 团队发文：用 GPT-6 Astra 与更省成本的 GPT-6.1 Sol 配合 Codex，做证据收集式清理（查 Slack、Statsig、性能画像表等）。团队自述合并 **1,400+** 个维护 PR、删除 **80 万+** 行；举例容器镜像 3.31GB→1.72GB。同 prompt 对比中，Sol Ultra 找出约 Astra Ultra **92%** 的有效项，API 成本约 **14%**（厂商自测）。
- **为什么重要：** 这不是新模型发布，而是可迁移的工程信号——先找证据再删，并把贵模型发现的失败模式回灌到更便宜配置的 prompt。
- **来源：** [OpenAI Developers](https://developers.openai.com/blog/maintaining-software-with-the-gpt-6-family) · [AIHOT](https://aihot.news/items/wn2lwzshkg8gt2sbjuj1qxd8y)

### 4. vLLM · 无置信头草稿模型也能做 Adaptive Verification
- **背景：** 投机解码在大 batch 时会算力打满；Adaptive Verification 需要按「被目标模型接受的概率」裁剪草稿 token。
- **发生了什么：** 2026-10-14 博客：对没有 confidence head 的 EAGLE / MTP / DFlash 等，用草稿 logits 的 `logit(q_max)` 在线拟合 logistic 回归，预测目标模型接受概率。随流量持续重拟合；`enable_adaptive_verification` 开启。有硬件/注意力后端等前提限制。
- **为什么重要：** 降低「必须重训带置信头草稿模型」的门槛，让更多现有 checkpoint 吃到 AV。
- **来源：** [vLLM Blog](https://vllm.ai/blog/2026-10-14-adaptive-verification-online-estimator) · [AIHOT](https://aihot.news/items/fuzrhjjahftxj9xj36god3pcf)

## 论文

1. **The Silent Failures in Agentic Data Science**（首次提交，[arXiv:2610.14115](https://arxiv.org/abs/2610.14115)）
   - **核心贡献：** 指出只看预测准确率与代码能否跑通，会掩盖数据泄漏、错误验证等方法论失败；在 220 个任务与专用失败测试套件上系统审计。
   - **与已有方法区别：** 把 agentic DS 评估从「下游分数」拉回「数据科学原则是否被违反」。
   - **代码/数据：** 文中称可复用测试套件；以论文与配套仓库声明为准。
   - **为什么重要：** 编程 Agent 进 notebook 时，「分数变好」可能正好与泄漏失败正相关。

2. **Long-Horizon-Terminal-Bench 2.0**（首次提交，[arXiv:2610.14146](https://arxiv.org/abs/2610.14146)）
   - **核心贡献：** 扩展长程终端评测：77 任务、最长约 3 小时、每 30 分钟检查点；稠密进度奖励 vs 终态二值判定。
   - **关键数字：** 稠密均值奖励远高于二值通过率（文中重建任务上约 0.653 vs 0.221），说明只看终态会丢掉大量中间进展。
   - **代码/数据：** 基准与任务构造管线见论文；**官方未在摘要中承诺全面开源全部场景生成器**。

3. **Harness²: Recursive Agent Harnessing for an Open World**（首次提交，[arXiv:2610.14224](https://arxiv.org/abs/2610.14224)）
   - **核心贡献：** 在无地面真值校验器的开放任务上，用 Propose-Probe-Compose 做 harness 递归改进，并把经验抽到持续改进 harness。
   - **为什么重要：** 把「改 prompt/工具编排」本身产品化，而不只依赖换更大模型。

4. **Should SLMs be in the Driver's Seat?**（首次提交，[arXiv:2610.14209](https://arxiv.org/abs/2610.14209)）
   - **核心贡献：** 云端模型写程序、端侧小模型在运行时解释用户私有数据——在 AppWorld 上相对纯代码 Agent 最高约 **+14.9pp** 成功率。
   - **为什么重要：** 直接回答 Cursor/本地 Agent 用户关心的隐私—能力折中：不是二选一，而是「程序 + 有界本地解释」。
