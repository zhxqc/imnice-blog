## 模型 / 产品

### 1. Kimi · K3.1 Pro 限流致歉与配额补偿（2026-10-26 约 04:14–07:10 北京）
- **背景：** K3.1 Pro 主线发布已在前几日日报覆盖；订阅用户随后遇到限流与额度异常消耗，直接影响付费体验与 Agent 子调用成本。
- **发生了什么：** Kimi 承认问题在己方、本应更早修复；对所有档位有效订阅会员做一次性用量重置，并补偿约 **25% 月度额度**（称约一周用量）；当前用量不足 25% 的将重置为 0；用量条预计在 PST 当日结束前反映调整。同时调整计划参数，减少不必要的 subagent 调用与过长输出，让配额更耐用。
- **为什么重要：** 国内旗舰订阅产品在「多 Agent / 长输出」默认策略上的运营纠偏信号；配额设计直接约束 Agent 用法。
- **来源：** [IT之家](https://www.ithome.com/0/1017/723.htm) · [AIHOT 事件](https://aihot.news/story/f8dac6dc-f133-47be-90ad-b17297774877)

### 2. Nanbeige4.3-33B 开源智能体编程模型【补录 / 二次传播】（HF 约 2026-10-24；本窗媒体密集转述）
- **背景：** ~30B 开源档位竞争激烈（Qwen / Gemma 等）；智能体编程 + 长上下文是差异化叙事。
- **发生了什么：** Nanbeige LLM Lab（BOSS 直聘）在 Hugging Face 以 **Apache-2.0** 发布稠密 **Nanbeige4.3-33B** 及 Base；模型卡宣称最高约 **524,288** token 上下文，主打 agentic coding / 办公协作；厂商表称在与 Qwen3.8-27B、Muse-Glimmer-30B、Gemma4-31B 等对比中多数基准领先（**官方测试，待独立验证**）。计划后续蒸馏更小的 3B。
- **为什么重要：** 又一个面向编码 Agent 的开源「教师模型」选项；无独立榜单前勿当作已验证 SOTA。
- **来源：** [Hugging Face · Nanbeige4.3-33B](https://huggingface.co/Nanbeige/Nanbeige4.3-33B) · [MarkTechPost](https://www.marktechpost.com/2026/10/25/nanbeige-releases-nanbeige4-3-33b-open-agentic-coding-model/) · [AIHOT 事件](https://aihot.news/story/c91a54ad-7c60-4add-9a60-24a2a9485ff6)

### 3. Browser Use · 编程智能体接入已登录 Chrome 指南（披露约 2026-10-25 08:00 北京；AIHOT latest）
- **背景：** 编码 Agent 常需操作已登录的网页（控制台、后台、文档），复制 Cookie 既脆弱又易踩安全红线。
- **发生了什么：** Browser Use 作者按 Claude Code、Codex、Gemini CLI、Cursor 等梳理接入**已登录 Chrome** 的方案与配置；Claude 订阅用户可用 `claude --chrome`（Claude in Chrome 扩展）路径；并解释 Cookie 复制为何不可行。
- **为什么重要：** 把「Agent 用真实浏览器会话」从玄学落到可迁移步骤，直接服务 Cursor / Claude Code 等工作流。
- **来源：** [Browser Use 原文](https://browser-use.com/posts/coding-agent-logged-in-chrome) · [AIHOT](https://aihot.news/items/j5auxb780hddyh0hlgekuw03h)
