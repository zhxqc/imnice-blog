## AI 新闻

1. **Gemini API 的 Computer Use 工具正式 GA**
   - 事件时间：2026-10-30。
   - 为什么重要：Google 已把 Computer Use 同时放进 Interactions API 与 GenerateContent API。浏览器、桌面和移动端 Agent 可以进入更稳定的产品接入阶段，但真正的工程门槛会转向动作白名单、人工确认、失败回滚和敏感数据隔离。
   - 关键变化/数字：官方更新日志明确写明 Computer Use 在两套 API 中进入 General Availability；这是 API 可用性级别变化，不等于所有模型和地区都具备相同能力。
   - 开放方式、规模、上下文、许可证：通过 Gemini API 接入；支持模型、计费、动作约束和上下文上限以官方文档为准；参数规模与许可证不适用/官方未披露。
   - 来源：[Google Gemini API 更新日志](https://ai.google.dev/gemini-api/docs/changelog#10-30-2026)

2. **Wiz 把 10 月多起 AI 开发者平台事件串成“Black October”风险观察**
   - 事件时间/发布时间：事件发生于 2026-10-06 至 2026-10-30，Wiz 文章发表于 2026-10-30。
   - 为什么重要：AI 开发平台把模型密钥、云凭据、构建系统和 Agent 工具集中在一起，攻击者不必突破模型本身，先拿到环境变量就可能转售调用权限或进行 LLMJacking。
   - 关键变化/数字：Wiz 列出 Fireworks AI、Andromeda、Zeabur、Lightning AI、OpenCode、Railway、Warp、CommandCode、Northflank 至少 9 起披露事件；文章还称两个案例合计可能产生超过 10 万美元的调用使用量，其中一个地址在 13 小时内发起约 170 万次 Bedrock 调用。Wiz 同时强调多数事件仍在分析，不能把它们视为已证实由同一漏洞造成。
   - 来源：[Wiz 原文](https://www.wiz.io/blog/black-october-for-ai-developer-platforms)

3. **Sierra 自报 ARR 超过 4 亿美元，Agent 商业化进入结果计费验证期**
   - 事件时间/发布时间：2026-10-30。
   - 为什么重要：Sierra 披露的是企业付费规模，而不只是注册用户或调用量；它把“完成贷款再融资、理赔、销售或客户留存”等业务结果作为收费依据，代表客服和业务 Agent 正在尝试脱离 token 计费。
   - 关键变化/数字：公司自报 ARR 超过 **4 亿美元**，Q3 新增超过 **1.5 亿美元**，从 2 亿美元增长到 4 亿美元用了 5 个月；另称已服务接近一半 Fortune 50。以上均为公司披露，未作独立审计结论。
   - 开放方式、规模、上下文、许可证：商业闭源服务；Agent 模型、参数规模和许可证官方未披露。
   - 来源：[Sierra 官方公告](https://sierra.ai/blog/our-customers-ambition-is-accelerating-our-growth)

4. **Toyota 与 Waymo 将于 2027 年在日本测试 bZ4X 自动驾驶车队**
   - 事件时间/发布时间：2026-10-30。
   - 为什么重要：双方合作从 2025 年的初步协议进入车队测试和日本本地制造阶段。若按计划推进，自动驾驶服务将从美国市场扩张问题，进一步变成整车厂、自动驾驶系统和本地运营协同落地的问题。
   - 关键变化/数字：Waymo 称双方将于 2027 年在日本测试并验证 Toyota bZ4X 自动驾驶车队，车辆将在日本爱知县丰田市的 Takaoka 工厂生产并集成 Waymo 硬件，后续计划考虑英国及其他 Waymo 已服务市场。
   - 开放方式、规模、上下文、许可证：Waymo Driver 与 Toyota bZ4X 的合作部署；传感器、模型规模和软件许可证官方未披露。
   - 来源：[Waymo 与 Toyota 联合公告](https://waymo.com/blog/2026/10/toyota-bz4x-partnership)

5. **NVIDIA 用 MonsterHouse 展示本地多模态语音 Agent 的完整链路**
   - 事件时间/发布时间：2026-10-30。
   - 为什么重要：这不是新模型发布，而是一个可运行的系统示范：ASR、对话、TTS、口型动画、视觉识别和状态记忆被压进单台工作站，说明本地 Agent 的竞争正在从单模型参数转向整条实时交互链路。
   - 关键变化/数字：NVIDIA 文章介绍的 MonsterHouse 使用 Nemotron Voice Agent、Nemotron ASR、Nemotron 3.5 Bolt E4B 4GB、Magpie TTS Zeroshot、Audio2Face-3D，以及 Nemotron 3 Nano Omni、YOLO 和 ByteTrack；运行在 NVIDIA RTX PRO 6000 Blackwell Max-Q 与 RTX PRO 4000 Blackwell 工作站上。官方记录的语音结束到音频输出中位延迟为 **1.70 秒**，缓存回复为 **0.72 秒**。
   - 开放方式、规模、上下文、许可证：NVIDIA 开放模型与本地工作站方案；文章明确提到 Bolt E4B 4GB，但没有在本文统一给出所有组件的参数规模、上下文和许可证，具体以对应模型卡为准。
   - 来源：[NVIDIA/Hugging Face 项目文章](https://huggingface.co/blog/nvidia/nemotron-halloween)

## 今日最值得跟进

1. **把 Computer Use 和 Agent 技能当作受控执行系统**：测试动作白名单、人工确认、失败回滚、提示注入和敏感数据访问，不要只测“能否点开网页”。
2. **把 AI 凭据从开发环境里单独治理**：平台密钥、云访问密钥、构建令牌和 Agent 技能都应采用短期凭据、最小权限、出站调用监控和异常费用告警。
